# AICO HOTL Relaunch 与首批用户试用计划

## 目标

这不是一次追求曝光量的广撒网。第一阶段只验证：

> 10 位已经使用 Claude Code 或 Codex 的个人开发者，能否理解 AICO、接通真实 IM、
> 完成第一个真实任务，并在 7 天内主动再用一次。

## 不从冷启动私信 GitHub 作者开始

直接私信陌生项目作者既生硬，目标也不准。第一批按信任距离分三层：

1. **3 位熟人样本**：已经使用本机 Coding Agent 的同事、朋友或技术群熟人。
2. **4 位内容自愿报名者**：从博客园、知乎、小红书、朋友圈或技术群发布真实案例，
   用表单或 GitHub Discussion 接受自愿报名。
3. **3 位开源社区样本**：只在对方公开表达过“远程管理本机 Agent、审批疲劳、
   长任务接手困难”时公开邀请；不群发、不伪装成 Issue、不自动私信。

项目 Owner 负责关系和最终邀请；Codex 负责为每位试用者生成最小配置、排障、整理反馈和
证据，避免 Owner 重新记住所有实现细节后才能开始。

## 对外邀请文案

> 我在做一个个人、本机优先的开源工具 AICO：从 Telegram 管理你已经在用的
> Claude Code / Codex。Agent 在明确边界内继续工作，遇到写入、Shell、未知或例外再找人，
> 并留下任务、审批和早报。
>
> 我现在只找 10 位已经日常使用本机 Coding Agent 的开发者做陪跑试用。不是问卷：
> 我会陪你接通一个真实仓库，完成一个真实小任务。预计 30–45 分钟，不上传仓库内容，
> 不要求长期运行。作为交换，希望你直接告诉我哪里看不懂、装不上或没有价值。

## 每位用户的陪跑流程

### 进入前

- 已经使用至少一个本机 AI CLI。
- 有一个可以安全试验的小仓库。
- 接受 Mac 保持在线；AICO 不是云端执行器。
- 不使用生产凭据、客户隐私数据或不可逆发布动作作为首个任务。

### 30–45 分钟会话

1. 3 分钟：只讲一句定位和一张能力图。
2. 5 分钟：运行 no-token demo，确认用户是否理解 task / approval / morning。
3. 10 分钟：接通 Telegram 和一个真实 Adapter。
4. 10 分钟：执行一个真实只读任务。
5. 10 分钟：执行一个会触发审批的小改动，再看 `/task`、`/audit`、`/morning`。
6. 5 分钟：让用户回答“下周你会在什么情况下再次打开它？”

### 只记录五个指标

| 指标 | 成功定义 |
|---|---|
| README → Demo | 用户无需口头解释即可跑起来 |
| Demo → Telegram | 用户愿意继续接真实 IM |
| Telegram → 首个任务 | 一个真实任务到达终态 |
| 接手质量 | 用户能从 `/morning` 或 `/task` 说出 done / blocked / next |
| 7 日复用 | 用户主动发起第二个任务，不由项目方提醒完成 |

如果前 5 位有 3 位卡在同一步，暂停招募，先修这个共同阻塞；不要继续增加功能掩盖漏斗问题。

## 真实案例素材：3 分钟视频，不是 3 分钟 GIF

GitHub README GIF 保持 30–45 秒，只负责让人看懂“IM 指挥、审批、早报、审计”。
三分钟真实案例使用 MP4 或带字幕录屏；GIF 太大、无法控制播放，也不适合呈现等待和解释。

建议脚本：

1. **0:00–0:20，真实痛点**：人在外面，从手机交一个范围明确的真实 bugfix。
2. **0:20–0:45，授权包络**：AICO 展示项目、负责人、当前权限；Lead 在范围内自行拆解。
3. **0:45–1:20，自主推进**：Reviewer 只读检查，Implementer 定位修改点，不反复询问已知事项。
4. **1:20–1:45，例外升级**：写文件或运行测试触发一次 `/approve`；展示未知/冲突时停止，而不是猜。
5. **1:45–2:25，真实执行**：批准后完成修改、测试和独立 Review，保留真实任务 ID 和审计。
6. **2:25–3:00，老板接手**：第二天 `/morning` 显示 done / blocked / risks / next，再用 `/view` 或
   `/audit` 深挖。

素材必须来自一次真实 Adapter + 真实 IM 跑通。允许剪掉等待时间和敏感内容，但不能用 fake adapter
冒充真实执行。README GIF 从该视频截取四个可读镜头；完整视频负责证明结果。

## 两周执行节奏

- D1–D2：恢复项目 Owner 自己的 15 分钟真实 dogfood，选定案例任务。
- D3：录制真实 3 分钟案例，生成 30–45 秒 teaser。
- D4：发布 `v0.1.0` 和案例文章，开放 10 个 design-partner 名额。
- D5–D10：完成前 5 位陪跑；共同阻塞优先于新功能。
- D11：做一次漏斗复盘，决定继续、收窄用户或修改安装方式。
- D12–D14：完成后 5 位，并统计 7 日复用的第一批信号。

## 停止条件

- 用户必须在项目方持续提醒下才会完成第二次使用。
- 首个真实任务无法在 45 分钟内跑到可解释终态。
- 需要项目作者手工修改 AICO 源码才能完成普通安装。
- 用户真正需要的是云端 Agent、企业多租户治理或 IDE 内交互，而不是个人本机远程控制。

出现停止条件时，先修定位或入口，不把它解释成“用户不会用”。
