# AICO 首批 Design Partner 执行包

## 本轮要验证的唯一问题

目标用户是已经在 Mac 上日常使用 Claude Code 或 Codex、并且有“离开电脑后仍要知道
Agent 做到哪、该不该批准、回来如何接手”需求的个人开发者。

两周漏斗固定为：

```text
10 位合格候选 → 5 位完成安装 → 3 位完成真实任务 → 1 位在 7 天内主动复用
```

这不是企业采购验证，也不以 Star、群人数或问卷好评替代真实任务。

## 候选分层

| 批次 | 数量 | 来源 | 为什么先找 |
|---|---:|---|---|
| A | 3 | 已知在用本机 Coding Agent 的朋友、同事、技术群熟人 | 信任成本低，可快速暴露安装问题 |
| B | 4 | 真实案例文章、朋友圈、知乎、小红书、技术群的自愿报名 | 有明确 opt-in，不做冷私信 |
| C | 3 | 公开表达过远程控制、审批疲劳、长任务接手痛点的开源用户 | 只在相关公开语境下邀请 |

不批量私信 GitHub 作者，不把招募伪装成 Issue，不自动抓取私人联系方式。

## 进入标准

候选人同时满足：

- Mac 上已经能独立运行 Claude Code 或 Codex；
- 有一个可安全试验的小仓库和可回滚的小任务；
- 接受 Mac 需要保持在线，AICO 不是云端执行器；
- 首个任务不包含生产凭据、客户隐私、付费发布或不可逆操作；
- 明确同意参与试用；案例公开另行 opt-in，默认匿名。

## 30–45 分钟陪跑

### 1. 三分钟建立心智模型

只讲一句话和一张图：

> AICO 是个人、本机优先的 Human-on-the-loop 控制层：Agent 在已知边界内推进，
> 写入、Shell、未知和例外回到你，结果通过任务、审计和早报交接。

### 2. 五分钟首用预检

```bash
env UV_CACHE_DIR=/tmp/aico-uv-cache uv run --python 3.11 aico demo
uv run aico init
uv run aico doctor
```

在安装 LaunchAgent 前，必须在同一终端做一次 Provider 只读登录探针，并前台运行
`uv run aico run`。真实自修复案例已经证明：终端已登录不代表受限后台环境一定能读取同一凭据。

### 3. 十分钟接通真实 IM

- 只用候选人自己的 Bot 和 owner-only 私聊；
- `/project <project>`、`/team`、`/inbox`；
- 先做只读任务，确认 IM、Adapter 和结果回传。

### 4. 十分钟完成一个审批任务

任务必须是可人工检查的小改动，例如修正文档、补一个已有测试断言或修复一处明确文案：

```text
/ask implementer <范围明确、可回滚的小任务>
/approve <short_id>
/task <short_id>
```

如果 Agent 遇到未知、冲突或越界，正确结果是停下并说明，不是硬凑 `done`。

### 5. 五分钟完成接手

```text
/audit 10
/morning
```

让用户自己说出：完成了什么、哪里阻塞、当前风险、下一步是什么。解释不出来就不算接手成功。

## 每位用户只记录这些事实

使用 [`design-partner-tracker.csv`](design-partner-tracker.csv)，不记录 Token、仓库正文或私人聊天。

- 是否从 README 独立跑通 demo；
- `doctor` 首个失败项；
- Provider 只读探针是否通过；
- 首个真实任务是否到达可解释终态；
- 是否发生审批，以及用户能否解释批准了什么；
- 用户能否从 `/task` 或 `/morning` 完成接手；
- 7 天内是否由用户主动发起第二个任务。

如果前 5 位中有 3 位卡在同一步，暂停招募，先修共同阻塞。

## Owner 与 Codex 的分工

| Owner | Codex |
|---|---|
| 选择真实关系、决定是否邀请、参与需要人情判断的沟通 | 按候选环境生成最小配置和任务模板 |
| 决定是否接受公开案例、最终发布渠道 | 做安装预检、排障、证据脱敏和会后摘要 |
| 在 IM 中批准具体风险动作 | 维护漏斗、发现共同阻塞、提出下一轮修复 |

Codex 不代表 Owner 自动联系候选人，也不在未确认时发送外部消息。
